## 6. 机制图景（修正版）

rel 项的实际行为由输入条件三态决定：
1. **饱和场景/良性输入**（4/5 场景、chess、多数 clean）：误差≈0，梯度≈0，纯噪声扰动；
2. **遮挡触发型灾难**（office m2 类、09c probe0+m0）：大误差大梯度，cos(g_R,g_base)
   从 +0.3 掉到 ~0；加 R 可局部改善但稀释 base 学习，且 100 步修不清 m2 型失败；
3. **视角组合型灾难**（09c probe1、office pair9）：80–130° 单相机旋转错，三状态救不了
   （pair9 例外：base 训练修好了，rel 训练没修好）；此条件下 md 与 g_R 一阶冲突（−0.78）。

eval 层面的 rel 有害（DA3 7scenes AUC −4.5%）可由 (1) 噪声扰动 + (2) 方向挤占/稀释
+ (3) 阻止 base 修复特定组合 共同解释，无需"饱和噪声"单一标签。

## 8. 下一步（按区分力排序）

1. **mask 触发型灾难的输入侧防御**：对 office probe0/pair5 的 m2 型失败做 mask 难度
   筛选（teacher conf 或 loss 阈值跳过灾难 mask），验证是否消除 rel arm 尖峰；
2. **rel 权重退火/门控**：只在 rel_rot 大于阈值的输入上加 R 项（利用其局部有效性，
   避免饱和场景噪声），office pair9 需要专门验证；
3. **09c probe1 型（视角组合）**：与 TTA 无关，属 4-view 输入组合选择问题——
   probe/训练对的 frame selection 应避开产生 90°+ 旋转歧义的组合（τ 或共视筛选可能不够）；
4. 梯度手术（PCGrad 等）优先级降低：冲突仅在特定条件（md vs R −0.78），且主问题是
   范数悬殊下的方向挤占，门控/加权比重投影更对症。
